# Participant UI Rules

1. Mobile first.
2. One dominant action per screen.
3. Use server-backed state, not guessed local state.
4. Show the smallest set of information needed for the current moment.
5. Keep buttons large and easy to tap.
6. Do not crowd the screen with table history or analytics.
7. Join, queue, and result flows should feel calm and obvious.
8. Use `layout.pen` as a starting point, but improve readability where needed.
9. Avoid generic dashboard visuals on participant screens.
10. Ranking on mobile should remain readable without pinch-zoom.
