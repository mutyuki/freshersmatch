# テストマトリクス

この文書は、「どの要件をどのテストで担保するか」を明示するための一覧である。

## 1. 運用ルール

- 各主要要件には `unit / integration / e2e / manual` の少なくとも1つを割り当てる。
- 自動化しない項目も空欄にせず、`manual` として理由を書く。
- 実装追加時は、この表も一緒に更新する。

## 3. 特に重視する整合性確認

以下は、関連する integration test で毎回直接 assertion する。

1. `participants.status`
2. `participants.current_match_id`
3. `participants.chip_balance`
4. `tables.status`
5. `tables.current_match_id`
6. `matches.status`
7. `matches.winner_claimed_by_participant_id`
8. `matches.winner_participant_id`
9. `chip_ledger.delta`
10. `chip_ledger` 行数

## 4. 自動テストで担保しにくいもの

以下は manual チェックも必要。

1. 会場Wi-Fiが不安定なときの運営オペレーションしやすさ
2. スマホでの片手操作しやすさ
3. モニター用ランキング画面の遠距離視認性
4. 実際の会場導線で「卓番号を見てすぐ動けるか」
